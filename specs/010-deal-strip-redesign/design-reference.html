The idea behind every option

The deal is the noun. Pages are lenses.

Loan, costs and rent describe the property, not a page. They should live with the scenario and be reachable from anywhere, while each page shows only the inputs it alone owns: extra payments, DSCR minimum, wealth assumptions, exit inputs.

A compact strip under the page title summarises the active scenario as chips. Click a chip to edit that one value in a popover. Edit deal opens a side sheet with every shared field, grouped in the order people think about a purchase.

Why it works
  • Every page's own content starts within the first screen.
  • Small what-ifs stay one click away, with the resulting change shown in the popover.
  • Pinned chips (blue) differ by page: rate, term and rent on Financing; price and appreciation on Wealth.
  • Reuses the ui-sdk Drawer already in AppShell. Same pattern on phone, as a bottom sheet.
Watch for
  • Validation errors need a home: a red chip plus an error count on Edit deal.
  • E2E tests that fill fields directly will need to open the sheet first.

Ideas to layer on top

Making the inputs feel less like a form

The deal as a sentence

Replace the chip row with a readable sentence. Each underlined value is an inline editor. It shows that loan amount is a result, not an input.

Buying a home with down, so borrowing $360,000 at for , renting it for /mo.

Click a value to cycle through sample amounts.

The monthly payment is the cost editor

Show the total payment as a stacked bar (P&I, tax, insurance, PMI, HOA). Click a segment to edit it. Six fields become one picture that's useful on every page. SegmentedBar already exists in shared-charts.

Scrub to explore

Drag horizontally on a field label to nudge its value, the way design tools do. The strip shows the live effect on the page's headline metric. That makes sensitivity tangible without a separate chart.

Show what each page uses

Each page declares which shared inputs it reads. The strip pins those chips first and greys the irrelevant ones, so the user knows what to tweak here.

Change ripple + undo

After any edit, briefly highlight the metrics that moved and show a toast you can undo. With inputs off-screen, this is how users know their edit landed.

First run expands, later visits collapse

A new or untouched scenario shows the full form inline as a guided setup. Once it's valid, the form folds into the strip. Missing pieces appear as chips ("Add rent to unlock cash flow") that open the sheet at the right field. That replaces the current "Fix the highlighted fields above" messages, which would otherwise point at fields that aren't on screen.

Recommendation

Build Concept A, with the sentence and payment bar inside the sheet

Implementation outline

  1. New DealStrip in shared-ui: scenario tabs, chips and the PITI total. It replaces ScenarioTabs at the top of each view.
  2. New DealSheet on the ui-sdk Drawer (right side on desktop, bottom on mobile). It hosts the existing LoanInputForm, CostBreakdownPanel and RentalInputsPanel, reordered as Property → Loan → Monthly costs → Rental.
  3. Each view passes pinned fields and its headline metric to the strip for the popover preview.
  4. Delete the repeated Loan, Real-estate cost and Rental sections from the four views (and leave them out of spec 009's page).
  5. Error routing: the strip shows an error count, and clicking it opens the sheet scrolled to the first invalid field.
  6. Update e2e helpers with an openDealSheet() step.
